# YJ-Pocket-Desktop · 产品需求文档

状态：2026-09-30，产品方向与验收基线。本文描述目标，不把规划功能算作已交付；实际能力见[实现对照](implementation-map.md)，目录迁移见[统一素材库规格](media-library-migration.md)。

## 1. 产品定位

**YJ-Pocket-Desktop 是一款可以装进口袋硬盘的小巧便携素材搜索和整理器。** 应用代码与个人素材彼此独立；用户可从内置盘、外接硬盘或其他已挂载磁盘发现照片、视频、音乐与录音，在一处浏览、检索、归档和回到原文件。便携意味着应用可以随盘移动、素材不必复制进应用包；不承诺在所有设备上免安装或绕过操作系统安全策略。

“像 Everything 一样轻快”既是交互目标，也是技术约束：索引优先只存文件名/路径与少量必要元数据，按文件系统能力选择增量机制，查询不重复扫描整盘；同时单独测量安装包、内存和索引体积。不是复制其界面、图标、搜索语法、代码或商标，也不表示已经集成 Everything。Windows NTFS 的 USN 日志不能原样套到 exFAT、网络盘或 macOS/Linux。设计依据见[轻量索引技术方案](search-index-architecture.md)和 Everything 的[索引说明](https://www.voidtools.com/en-us/support/everything/indexes/)。

### 用户故事

1. 摄影者插入 DJI、iPhone 导出盘或工作硬盘，先看见可用磁盘和可扫描范围；选择授权后才建立本地索引。
2. 在几块盘之间输入作品名、日期或关键词，快速找到原文件，知道它在哪块盘、盘是否在线、能否预览。
3. 将散落素材按 `Pictures / Videos / Music / Recordings` 分类，但移动、重命名、去重等改变原件的操作必须预览并确认。
4. 拔掉硬盘后仍能看见索引中的条目及“离线”状态；无法打开原件时不展示过期预览为可用文件。重新接入后校验并恢复。
5. 复制应用包到另一块硬盘或另一台电脑，仍能启动应用；授权范围、索引、缓存和密钥不意外随公开代码或安装包上传。

### 非目标与安全边界

- 不自动扫描整台机器、系统目录、其他用户目录、网络共享或云盘；**自动发现磁盘 ≠ 自动索引内容**。首次扫描范围需由用户明确选择，之后可为已授权的同一卷自动更新。
- 不默认移动、删除、改名、上传、转录或分析原始素材。浏览和搜索只读；整理原件属于另一个需确认的操作流程。
- 不承诺所有文件格式可直接预览。DNG、LRF、HEVC 等有保留原件与降级处理规则。
- 首版不做内容语义搜索、照片人脸识别、跨设备同步或与 Everything 进程的强制依赖。

## 3. 磁盘与素材源（PRD-SOURCE-001）

### 数据模型

一个素材源至少包含稳定的内部 `source_id`、卷标/用户命名、卷身份（平台可得时）、当前挂载点、文件系统、授权扫描根、排除规则、上次成功扫描时间、在线/离线/需重新授权状态。**盘符或挂载路径不是唯一身份**：`E:` 可以先后属于不同硬盘，同一硬盘也可能换盘符。无法可靠识别同一卷时必须请求确认，不能复用旧索引覆盖新盘。

默认的 `D:\YJ-Media` 只是当前机器的已选素材源，不是产品架构中唯一允许的路径。来源可含 DJI-Action、DJI-FLIP、iPhone 录音和相册，也允许将来有多个盘上的同类素材。公开代码和发布包不包含这些素材。

### 发现与授权

- 启动、插入或移除磁盘时刷新“可用磁盘”列表；发现过程只读取卷级信息，不遍历文件。对于不可读卷、网络盘和云端占位文件，给出原因与手动选择入口。
- 用户选择一个或多个文件夹作为扫描范围，并可排除系统目录、缓存目录和私密目录；展示预估数量/空间与首次扫描可能耗时。设置页可暂停、移除或重建单个源的索引。
- 未授权卷、被排除路径、符号链接/重解析点越界路径不得进入索引。平台权限不足时降级到用户选定目录的普通遍历，不要求提权才能完成基本功能。
- 热插拔/重启后，同一卷恢复在线状态；拔盘时保留元数据并标离线。重新接入后比较卷身份及变化，不用“路径相同”直接推断内容相同。

**验收：** 用两块卷和一个会变化的盘符测试，A 盘改盘符后不会生成重复作品；B 盘占用 A 原盘符不会拿到 A 的索引；拔盘后不能打开/移动离线文件；未授权卷在索引和结果中均不存在。

## 4. 索引与搜索（PRD-SEARCH-001）

### 索引字段和更新

首版索引每个可访问文件的 `source_id`、卷内相对路径、名称、扩展名、类别、字节数、文件修改时间、可获取的创建/拍摄/录制时间及其来源、在线状态、最近扫描版本。只把路径和元数据放入本机索引，不把原文件复制进去。文件名、目录名、扩展名变化和新增/删除要更新；监听不可靠或断开后用有边界的重新扫描校正。索引写入应可中断恢复，损坏时可重建，不影响原件。

首版检索范围是**已授权并完成索引的素材源**。关键词默认匹配文件名与相对路径，忽略大小写，支持中文、空格和常见 Unicode 文件名；多词默认为 AND。提供明确的“所有源 / 指定源 / 当前目录”和图片、视频、音频、录音、其他文件筛选。输入变化可取消上一轮查询；结果分页或虚拟化，不一次渲染全部条目。M2 可采用自有本地索引，不依赖 Everything 已安装；具体存储与平台加速策略由实现方案决定。

### 日期与内容边界

| 媒体 | 首选日期 | 回退日期 | 关键词扩展（后续） |
| --- | --- | --- | --- |
| 图片 | 可读取的拍摄日期 | 修改日期 | 标题/描述、EXIF 可搜索字段 |
| 视频 | 可读取的录制日期 | 修改日期 | 标题/元数据 |
| 音乐 | 可读取的标签日期 | 修改日期 | 曲名、艺术家、专辑 |
| 录音 | 可读取的录制日期 | 修改日期 | 已有对话稿与纪要文字 |

界面必须显示所用日期及来源；不能把修改日期称为拍摄日期。用户时区下的单日与起止日期均包含边界日，非法范围提示错误。没有可靠日期的文件保留在关键词结果中，并用“日期未知”单独处理。已有转录全文检索属于后续增强；尚无对话稿时按文件名/目录/日期仍可找到录音。

### 搜索界面

- 顶栏中的银色放大镜图标是当前可见的统一入口（历史 Dock 中也有同一图标）。**当前实现仅聚焦 Finder 的“搜索当前文件夹”输入框**；M2 才切换为全局搜索面板。M2 面板显示作用域、索引进度、结果总量、来源盘、相对路径、类型、日期来源、在线状态；提供清除条件和打开原文件。
- 键盘可聚焦/提交/清空搜索；结果可按键盘逐项访问，屏幕阅读器有输入名、结果数和加载状态。390px 窄屏仍可选择范围与类型。
- 无结果需区分“匹配为空”“仍在索引”“磁盘离线”“权限不足”；搜索不自动播放、转录或发网络请求。

### 可测性能目标（目标值，不是当前实测）

在基准机及固定样本集（本机 SSD、10 万条文件名索引、1 万条查询结果）记录硬件、文件系统、冷热缓存与测试脚本：已建索引的关键词查询 p95 ≤ 200 ms 返回首批 50 条；输入时主线程不出现 > 100 ms 的持续卡顿；索引与搜索内存、磁盘占用随条目数可观测且可清理。M2 索引模块/辅助件带来的安装包增量目标 ≤ 5 MiB；当前 Electron 整包约 96.3 MiB，不能声称已达到 Everything 的包体积。机械盘、exFAT、网络盘首扫不套用 SSD 时限，必须显示进度、暂停/恢复并避免持续满速占用。阈值若因实测调整，需在规格中记录设备与原因。

**验收：** 四类跨子目录样本分别测试单词/多词、中文、大小写、路径、单日/日期范围及组合；盘符交换、拔盘、断电中断索引、文件改名/删除、权限被收回后结果准确且有状态说明。搜索结果打开的是经当前卷身份校验的原文件，不是旧盘符下的同名文件。

## 5. 浏览与整理（PRD-ORGANIZE-001）

搜索结果可进入已有 Finder、画廊、视频/音乐播放器和录音页面；无法预览的格式保留文件条目、原件位置与兼容提示。分类建议使用 `Pictures / Videos / Music / Recordings`，来源层级（设备、日期、相册或项目）默认保留；DNG 原片、LRF 代理、侧车文件不因界面不可预览而丢弃。

整理操作采用“计划 → 预览 → 用户确认 → 执行 → 核验/可恢复记录”。默认不覆盖目标文件；同名不同内容列冲突，重复文件只建议、不自动删除。跨卷移动按复制、校验、再请求确认移除源文件的安全策略设计；不把未完成复制标为成功。每次执行展示来源、目标、数量、字节数、跳过与失败项。录音 HTML、assets、转录缓存作为有关联的档案整体处理，不能只移走 `.m4a` 破坏引用。现有一次性 `D:\YJ-Media` 迁移是历史操作，不等于通用整理功能已经实现。

## 6. 便携、隐私与发布（PRD-PORTABLE-001）

- Windows 优先交付含运行时的版本化便携 EXE，构建输出在 `dist/packages/`；安装包与代码分离，不携带用户媒体。macOS/Linux 需各自构建和验收，不能由 Windows 构建结果推断可用。
- 应用、索引、预览/转码缓存、密钥是不同数据层。默认将索引与缓存留在本机用户数据目录；若未来支持“索引随盘携带”，必须明确让用户选择、加上隐私提示和可清理机制。
- 本地服务只监听回环地址；搜索和缩略图不调用远程服务。录音转录使用外部服务时，必须另行明确触发并标示数据离开本机。
- 公开 GitHub 仓库仅包含代码、规范和可发布的原创小型静态素材，采用 MIT 许可证；素材库、索引、缓存、私人截图、密钥、构建产物均不提交。版本与发布流程见[发布规格](release-process.md)。

## 7. 交付判定与待决问题

M1/M2/M3 各自完成对应验收后才更新 README 的“已实现”描述。当前只承诺独立素材库与单目录浏览/过滤；多盘自动发现、全局搜索和安全整理均为规划。需要在实现前确定：首个平台的卷身份获取方式；网络盘是否纳入 M1；默认排除规则；iPhone 相册的实际来源路径；索引是否允许存在可拔插盘上。上述选择不能由现有 `D:\YJ-Media` 目录结构自动推断。
