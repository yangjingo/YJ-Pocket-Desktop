# YJ-Pocket-Desktop · 设计规格

状态：持续更新，2026-09-30。本文描述界面目标与验收边界；当前功能和视觉进度见[实现对照](implementation-map.md)，文档总入口见[文档导航](../README.md)。

## 设计命题

把可放进口袋硬盘的素材搜索和整理器呈现为一台拟物电脑。用户打开应用后，照片、录音、音乐、视频各有清楚的物理隐喻，背后读取真实的本地文件。当前只读取一个指定素材根目录；多盘发现和授权索引见[产品需求](PRD.md)，轻量实现见[索引技术方案](search-index-architecture.md)。桌面结构参考 Gemini 原型，设备材质参考[播放器图片](../ui/music-player-reference.md)与[Inspora 案例](../ui/inspora-references.md)；产品名称为 **YJ-Pocket-Desktop**。

原始 Gemini 桌面参考和原型文件留在未公开的本地资料中，不随源码发布。原型里的图片、视频和部分播放按钮是演示素材或演示状态；具体可用行为以本规格和本地媒体服务为准。

## 信息架构

```text
YJ-Pocket-Desktop 全屏桌面
├─ 顶栏：品牌与本地容量 / 应用入口 / 搜索 / 设置 / 本地化日期时间
├─ 桌面物件：照片 / 视频 / 音乐 / 录音 / 通用文件夹
├─ 窗口：照片看片台 / CRT 视频 / 黑胶唱机 / 磁带机 / Finder / 设置
│  └─ Finder：媒体根目录 → 各现有文件夹作为子房间 → 文件预览
└─ Dock：Finder + 搜索 + 四个媒体应用 + 设置，显示打开状态
```

桌面摆四类素材档案与一枚通用文件夹；通用文件夹进入 Finder，设置保留在顶栏与 Dock。顶栏银色搜索图标目前仅聚焦 Finder 当前文件夹过滤框，待索引能力实现后才成为跨盘搜索。各媒体应用目前共享独立于代码目录的 `D:\YJ-Media` 这一个默认根路径，录音档案位于其中的 `Recordings/IPhone-Voice`。目录安排与迁移验收见[统一素材库规格](media-library-migration.md)。

## 体验原则

1. **一个入口**：Windows 便携包输出到 `dist/packages/`，打开后在 Electron 窗口显示桌面；再次点击聚焦已有窗口。该设备因企业签名策略尚未完成 EXE 启动验收。浏览器模式可运行 `npm start`，访问 `http://127.0.0.1:8765/`。
2. **真实反馈**：转轮、唱片、进度条和计时器由实际媒体播放状态驱动。文件读取、转换、失败、空库都有明确状态。
3. **以内容为主**：桌面留白、实体应用物件、内凹输入和少量橙色功能点；高对比内容区保证长文件名、字幕和纪要可读。
4. **本地优先**：页面由 `127.0.0.1` 服务提供，媒体来自配置的磁盘路径；设计不依赖远程示例图或 CDN。MiniMax Key 只在本机设置与 CLI 中使用。
5. **窗口可控**：每个应用可聚焦、移动、最小化、关闭和最大化。小屏改为可滚动的单窗口布局，媒体控制始终可触达。

## 接下来的验收顺序

1. 基于当前 Three.js 3D 陈列台，在桌面与窄屏浏览器复核物件点击、路径、文件、设置、语言、播放与窗口操作；发现的问题回填[当前验收记录](../ui/object-archive-3d.md)。
2. 按[产品需求](PRD.md)分阶段实现磁盘发现、授权索引、全局检索和整理，并完成真实文件验收。
3. 前端 UI/UX 确认后重新生成 Windows 包，检查启动、单实例和媒体流程；macOS/Linux 在各自系统单独构建和验证。
